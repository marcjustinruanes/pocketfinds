On the production host, configure a service-account task/cron that runs `php artisan schedule:run` every minute in the deployed application directory, or supervise a persistent `schedule:work` process. Use the production PHP binary and environment, persistent shared cache for locks, private logs and failure alerts. For multiple scheduler hosts, select one owner or review a shared single-server locking strategy. Observe successful runs across at least two five-minute boundaries and a controlled staging obligation reaching the expected state. Do not use a production mutation command as a read-only test.
- [ ] **Queues:** the configured queue driver is database. Verify worker supervision, retries and failed-job alerts for the wider application's queued work. Do not infer worker health from the PHP web server or scheduler listing.
- [ ] **Recovery operations:** set backup frequency, retention, encryption, off-host copies, recovery objectives and responsible operators. Back up private proof storage and the existing application encryption key securely in addition to SQL; test restoring linked evidence and file permissions. Do not regenerate the application key during deployment.
- [ ] **Finance operations:** train receipt reviewers to distinguish buyer-to-Seller GCash, Seller commission payments, company remittances, COD withholding, refund reimbursements and Seller credits. Define evidence standards, disputed-reference handling and daily reconciliation ownership. Confirm procedures for legacy/already-paid orders, refunds above original product funds, partial quantities and separate platform subsidies. The revenue workspace is not a complete profit-and-loss, tax or provider-fee accounting system.

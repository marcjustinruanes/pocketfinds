# Buyer commerce

Buyer features use the existing pages: flash sales in Home → Deals; returns/refunds in the Orders tab after Cancelled; product reviews in completed orders; email verification and vouchers in My Account; shipping, vouchers, and checkout in Cart. The standalone Wishlist is at `/buyer/wishlist`, linked from the same wishlist icon as the guest storefront. Old `/buyer/commerce` links redirect to these destinations.
Seller settings use My Account (vacation mode, regional shipping rates), Inventory (flash sales), Vouchers, and Order Management (Return / Refund). Administrators manage platform/shipping vouchers under Products, and return escalations/repayment records under Complaints & Disputes. Old commerce-page URLs redirect to these native pages.

Seller, admin, logistics and rider account pages share registration-style name/mobile validation, region-filtered address selectors, postal codes, verified email changes and complex passwords. Seller/logistics/rider profile and address changes still require existing admin review; email verification and password changes are self-service. Real notifications are shown alongside operational alerts, with an ownership-scoped Mark all as read action. Rider delivery details retain the order's saved destination region and postal code.

- Sellers must configure a rate for every supported delivery region and enter product weights in grams. A missing rate or weight blocks checkout. Shipping is first-kilogram price plus each additional rounded-up kilogram.
- Vacation mode leaves listings visible and prevents new purchases. Existing payments and orders remain available for fulfillment.
- Vouchers have start/end dates, limits, minimum spend, optional discount caps and seller ownership. Checkout allows one store voucher per shop, one platform voucher, and one shipping voucher. A replacement of the same kind replaces the previous selection. Discounts cannot exceed their merchandise/shipping basis. Existing store discounts, free-shipping vouchers and platform discounts are imported with historical use counts preserved. Imported platform codes start with `PLAT` and appear in the voucher list. Existing cashback records remain in their original table.
- Flash sales have a scheduled period and limited quantity. Excess units use the regular price and appear separately in the checkout quote. Reminders are in-app notifications, sent once within five minutes before the sale starts or during the sale when requested late.
- Email changes require the current password and a code sent to the new Gmail address. Codes expire after five minutes. The original email stays in use until verification succeeds.
- New GCash reservations expire after one hour. Proof upload is not automatic payment verification. Existing seller verification remains required.
- Returns require selected order items, a reason, description and private photo evidence. Requests are accepted within seven days after delivery before order completion. A seller must respond within three days; otherwise the request is approved automatically. A buyer may escalate a rejection within three days. Returned stock is restored only when the seller confirms receipt, once. The administrator records an actual refund transaction reference after repayment; this application does not initiate a payment-provider refund. Item refunds deduct allocated merchandise discounts and never exceed the amount paid.
- Reviews are per order item, up to 500 characters and five JPG/PNG photos of at most 5 MB each, within 30 days after completion. Reviews may be edited once. Public names are masked.
- Delivery address books accept at most ten entries. Region and four-digit postal code are required. Phone inputs show a fixed `+63` prefix and accept the ten national digits starting with `9`.

Run `php artisan schedule:work` continuously to process reminders, GCash expiry and return response deadlines. For production, supervise it as a service or run `php artisan schedule:run` every minute. Schedule inputs currently use the application's displayed timezone (UTC).

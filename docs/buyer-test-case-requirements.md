# Buyer requirements from the mobile black-box test cases

Sources: `Mobile_Blackbox_Test_Cases_Buyer_Modules (1).xlsx` and `Mobile_Blackbox_Test_Cases_Account_Creation-Buyer (1).xlsx`.

Scope: 42 registration cases + 131 buyer-module cases = 173 cases. This extracts expected requirements; it is not a pass/fail audit or a verified list of missing features. No app or website code was changed.

## Rules to reconcile first

Both Assumptions sheets explicitly say their rules are marketplace examples, not rules taken from this system. They do not automatically override prior user instructions.

| Topic | Workbook expectation | Project instruction or known behavior |
| --- | --- | --- |
| Age | 18 (TC-BUY-007) | User requested 16. Retain 16 unless changed by the user. |
| Signup/status | Register Unverified, then OTP, then Active (TC-BUY-001/023) | Contact verification before application; pending administrator approval. |
| Email | Any valid unique email; example.com fixtures (registration A3) | Website-guided signup currently Gmail only. |
| Names | 2?50 characters; letters including ?, spaces, hyphens, apostrophes, periods (registration A2) | Website profile rules are more restrictive. Agree one consistent rule. |
| OTP expiry | 5 minutes (TC-BUY-026) | Current mobile signup challenge: 10 minutes. |
| Profile edits | New name visible after refresh/re-login (BUY-ACCT-001) | Current identity/address changes require admin review. |
| Phone | 09XXXXXXXXX or +639XXXXXXXXX; reject other lengths (TC-BUY-014) | Current signup also accepts 10 digits starting with 9. |
| Cancellation | Stop buyer cancellation at Ready for Pickup (BUY-CAN-004) | Previously requested flow allows eligible cancellation until actual pickup. |
| Electronic payment | Gateway/card or e-wallet, payment reference, one-hour unpaid auto-cancellation (B9) | Existing GCash uses reservation, receipt and seller verification. Connecting a GCash profile is not a gateway. |
| Login persistence | Persist through app close and phone restart (M9) | Current login offers Remember me. |
| Logout landing | Stay at Login; no private screens on Back (TC-BUY-042) | Current app returns to guest dashboard; exact landing and private-data protection are separate criteria. |

The buyer-registration field list has first/last name, email, mobile, birthday, password, confirmation and Terms/Privacy acceptance. It does not instruct removing existing ID/selfie, username, address, Google or approval features.

## Requirements applying across modules

- Enforce validation, role access and record ownership on the server as well as in the app. A denied request exposes no other user data.
- Actionable field/form errors; preserve recoverable input; no crashes, freezes, raw server errors or false success.
- Idempotent account creation, checkout, payments, cancellation, messages and other submissions: retries never duplicate records, charges, stock restoration or notifications.
- Verify persistence and side effects after refresh/reopening and in the other roles involved.
- Image type is checked by file content. Normal image rule: JPG/PNG, at most 5 MiB (5,242,880 bytes); the exact limit passes. PDF support is for document uploads, not every image field.
- Mobile: correct keyboards, hidden passwords without suggestions, OTP paste/autofill and elapsed-time countdown, interruption/rotation state retention, offline recovery, permission explanations and Settings access, camera/gallery/files when appropriate, unsaved-change confirmation and safe logout navigation.
- Small/large screens, light/dark mode and largest system text remain readable and scrollable; keyboard never blocks the active input or submit button.
- Push notifications go only to involved users; tapping opens the related screen even from a closed app. In-app notifications continue when push is disabled.

## Testing setup needed

- Installed Android build; record device, OS, build and network. Include iOS only if supported.
- Seller fixtures first: buyers and sellers, products/variants/prices/stock/weights, categories, sales/flash slots, vouchers/wallets, addresses and shipping-rate/serviceability data from Test Data.
- Orders in each lifecycle state, controllable boundary timestamps and hub/courier events for tracking. Their dependencies do not authorize website edits.
- Mail catcher or authorized test inbox; payment sandbox if gateway rules are adopted; two sessions/devices for cross-device cases; push and deep-link setup.
- Sample uploads plus exact-size/oversize, unsupported and disguised files. Use fictional/sample identity documents.
- Traffic proxy for tampering/direct-request cases; mark Blocked if unavailable. Record actual result/status and screenshot/video evidence. This review marks no workbook case Passed.

| M8 | Back navigation | The Android Back button and iOS swipe-back go to the previous screen. Leaving a form with unsaved changes asks the user to confirm discarding them. After logging out, Back never shows a logged-in screen. |
| M9 | Login session on the phone | The app stays logged in after it is closed, reopened or the phone restarts, until the user logs out, the password is changed (which also ends the session on the user's other phones), or the session token expires. |
| M10 | Push notifications | Status changes, approvals and chat messages also send a push notification to the phone of each user involved, and to no one else. Tapping a notification opens the related screen, even if the app was closed. If notifications are turned off in phone Settings, the in-app notification list still works. |
| M11 | Deep links and direct requests | Share links and email links (activation, product, store) open the matching screen in the app, or a mobile web page if the app is not installed. Access rules are enforced by the server: a deep link or a direct API request for another role's or another user's data is refused (401/403, an access-denied screen or a redirect to home). Cases that capture or send a request directly need a proxy tool on the test phone (for example HTTP Toolkit, Charles or mitmproxy). If your group cannot capture app traffic, mark those cases Blocked and write 'no proxy' in Remarks. |
